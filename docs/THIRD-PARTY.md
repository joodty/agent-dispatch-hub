# 第三方来源与许可边界

Agent Dispatch Hub 使用外部项目提供 DSH 执行与桥接能力。外部源码通过 `dependencies.lock.json` 中的 Git URL 和完整 SHA 固定，在用户状态目录下载；本仓库不把外部源码复制为自己的实现，也不修改或重新声明它们的许可。

`packages/dsh-companion` 是本仓库新增的包装与准入实现，通过 DSH 公开 Host 服务调用工作区、会话和工作目录能力，不内置 DSH 运行时代码。它不替代外部 bridge 的消息认证传输，也不改变外部项目许可。

| 外部项目 | 当前已知来源与许可证据 | 使用方式 |
| --- | --- | --- |
| DSH sync fork | 当前使用 sync fork，原始上游为 Walvez；该项目提供 MIT 许可。具体来源与固定提交以锁文件为准。 | bootstrap 获取固定版本，保留其许可与来源信息。 |
| DSH bridge | 上游为 knottttt；所检查的固定提交中没有 LICENSE 文件，也未找到明确许可声明的证据。不能据此将其标记为 MIT 或其他开源许可。 | 仅通过锁文件引用外部 Git 项目，并在用户状态目录获取固定版本；hub 不内置或重新许可其源码。 |
| npm 依赖 | 直接依赖及版本见 `package.json`，完整解析结果见 npm 锁文件；各包遵循自身许可。 | 按项目依赖安装，不将 hub 的许可声明扩展到第三方包。 |

更新依赖时应重新核对目标提交的许可文件、来源声明和分发内容。此处说明当前证据与仓库使用边界，不代表为许可缺失的第三方项目补充授权。

v0.3 的独立只读接口、跨进程并发协调和文件记录参考了 [deepseek-as-subagent](https://github.com/PsChina/deepseek-as-subagent) 的能力划分。本仓库按 DSH 的公开工具与会话接口另行实现，没有加入该项目、依赖其 Python 运行时或复制其源码；文件记录采用有界元数据快照，不声称实现其逐次修改日志。
