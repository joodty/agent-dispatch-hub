## 真实模型与文件

目标为已有 `office` 配置及其独立任务目录映射，DSH 为 0.2.1-rc.3，当前模型是 WorkBuddy / DeepSeek‑V4.1‑Flash / high。测试前通过 MCP 核对实例身份与已配置工作区；新建独立测试任务，没有改变原映射或正在执行的旧任务。

1. 通过新的 stdio MCP 服务派发一个刻意缺少测试标记选择的任务。DSH 遵循 `adh-question` 回复协议，提出 blue / green 选择题并结束本轮。
2. 新建 MCP 客户端进程执行 `hub_wait`，返回 `needs_input`、`completed:false` 和问题 ID。原始回执仍记录该轮真实完成。
3. 再启动 MCP 客户端进程调用 `hub_answer`，选择 blue。重复同一参数调用，返回同一个 request ID 和 `duplicate:true,promptSent:false`。
4. 同一 DSH 会话继续执行，写出 `decision-proof.txt`，返回完成。原生模型选择保持不变。
5. 通过 `hub_verify` 核对 DSH 工作区归属及实际 cwd，通过 `hub_artifact` 读取文件，并独立读取磁盘文件核对，内容均为 `ADH_DECISION_OK=blue`。`hub_questions` 中问题状态为 `answered`。

原始回执、回答确认和验收证据保留在运行机器的仓库外私有测试目录，没有提交连接文件、认证信息、模型历史或个人路径。测试产物保留在该任务的独立目录供复查。

## 尚未证明的范围

本次真实目标仍安装 placement v0.2 companion；问答回复协议不依赖新 target HTTP 接口，因此无需升级插件即可验收。v0.3 原生只读限制、目标端锁和文件审计尚未完成真实验收，继续保留在 [独立预览 PR #2](https://github.com/joodty/agent-dispatch-hub/pull/2)，本次不随问答功能合入主分支。

远程实例、其他提供方和其他操作系统未做真实问答验收，采用已有路径与目标切换模拟测试。此功能要求模型按协议输出；不转接原生 `ask_user_question`，也不自动唤醒已空闲的 Codex。具体边界见 [使用说明](README-QUESTIONS.md)。没有做提供方积分账单对照，不宣称问答协议一定降低费用。
