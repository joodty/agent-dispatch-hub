# v0.2 验证记录

验证日期：2026-10-26。此记录区分可复现测试与作者环境实测；接手安装仍须核对自己的实例、目录和权限。所有公开示例使用占位值，不含实际实例 ID、凭据或个人路径。

## 自动测试

`npm test` 覆盖原有安装、配对和配置保护，以及新增加的能力：

- 按实例绑定工作区，归属与实际执行目录分别记录；不同任务生成独立子目录。
- 工作区缺失、禁止创建、错误实例、已存在的任务目录和不完整准备过程拒绝。
- 同任务并发准备与重启后的重复请求不创建第二会话，计划变更不能复用原任务。
- 切换默认目标不改路由，连接/实例变更拒绝旧任务；范围变更禁止追问，保留原任务读取、等待与取消。
- v1 回执必须显式绑定，绑定不修改原回执或 DSH 会话。
- 初始等待与后续等待均不能覆盖并发追问或取消结果。
- 请求响应丢失后保留待确认 request ID，重复发送被拒绝；显式同内容重试复用 ID 与游标，目录漂移后仍保留后端完成证据。
- Windows、UNC、POSIX 路径按目标规则处理，覆盖目录边界、遍历、保留名称、驱动器相对路径、ADS、模板占位及真实路径越界。
- 托管 cwd 缺失时不调用 DSH 原生回落，未托管会话继续原行为。
- 产物读取基于实际 cwd，拒绝遍历、符号链接越界、非普通文件、超限及读取期间变化。
- 本机/远程共用协议；远程使用模拟认证与 HTTP，不向其他真实实例发请求。

`npm run check` 检查版本、固定依赖、示例 JSON、文档链接与路径/凭据泄漏。测试里的虚构路径有逐行标记，不排除整个测试目录。`git diff --check` 检查补丁空白问题。

## 公司本机实测

只使用已明确选定并授权的 Windows 本机 DSH 0.2.1-rc.3，保持其当前模型 `qfmodel / xhigh`。新配套插件通过该实例原生插件管理 API 安装和加载，未操作桌面、未重启应用。安装前保留 profile 文件备份。

先通过 API 读取实例身份与原生工作区，核对工作区路径、已有任务根目录、实际源码和范围，再显式添加验收映射。保留旧映射、默认目标及所有旧回执。

| 验收入口 | 实际核对 |
| --- | --- |
| Hub 派工与等待 | 新会话进入选定原生工作区；实际 cwd 是新任务子目录，初始目录仍是原生工作区路径 |
| 模型文件产物 | 创建带随机值的 JSON；目标端 API 与本机文件分别读取，随机值及 `37 × 43 = 1591` 一致 |
| MCP stdio 的 `hub_dispatch` | 第二个新会话在同一选定工作区内，实际 cwd 与第一个任务不同；模型生成第二份独立随机值产物 |
| `hub_verify`、`hub_artifact` | 经 MCP 核实工作区、实际 cwd 和文件；同时读取原生 `session/projections`，目录投影一致 |
| 旧会话保护 | 比较安装/验收前后的原生工作区成员，原有成员保留在原归属，没有移动、停止或重派旧任务 |
| 模型设置 | 原生模型投影的上次使用与下一次选择保持原配置 |
| 回执丢失恢复 | 在新验收任务上模拟“后端已接纳、控制端未确认”，按原 ID 只读核对，不再次发送；实际只有一条用户任务消息，产物通过 API 与本机读取核验 |

私有验收证据保存在安装机器的仓库外，公开记录只说明过程和范围。同事不能把此结果当成自己的安装已经通过。

## 尚未覆盖或受后端限制的能力

- 远程真实实例及其他目标操作系统尚未真机验收；统一路径与协议经过模拟测试，不自动连接未提供的实例。
- 依赖 DSH rc.3 公开 Host 服务。其他版本须重新验证服务及目录投影契约；不支持时应拒绝加载/派工。
- DSH 当前沙箱写根取初始工作区路径，因此任务 cwd 必须位于该工作区内。插件不自动改变权限。
- 配置读写范围为显式任务指令；插件产物读取检查范围，但不强制限制模型所有文件工具。要求任意范围强制隔离的配置会报不支持。
- 执行期间应保持插件加载与状态目录完整。插件被卸载或外部进程主动修改目录/会话，属于需要重新核对的环境变化。
- 文件读取实施真实路径及文件前后校验；它不是对抗同机特权进程并发更换目录的操作系统隔离边界。
- 部分失败可能留下显式创建的目录、工作区或未发任务的空会话。保留已知身份供排查，不自动清理或重复派发。
- 当前 DSH 的相同 request ID 重发行为不能当作可靠去重保证。`retry` 仅核对历史/队列，不重发；未能确认时保留待确认状态，由用户决定是否显式取消并进一步核对。
