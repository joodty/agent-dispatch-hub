# 独立消息通道验收

2026-10-26，仅使用用户明确选定的公司 Windows 本机 DSH。没有连接家用或其他真实远程实例，没有控制桌面，没有切换主会话或 DSH 的全局模型。

## 自动验证范围

新增测试覆盖收件箱原子事务与重启读取、损坏/符号链接/超限拒绝、成员认证与收件箱隔离、稳定请求键去重、不同内容冲突、项目预算、忙时排队、实例/映射/工作区/cwd 漂移、win32/posix 目标路径及原生工具来源身份。

调度集成使用模拟两端，覆盖并发 worker 不重复启动、正常完成与恢复竞争不重开已回信状态、晚到失败不污染已确认投递、响应丢失只确认旧请求、领取后退出的显式恢复、工厂失败释放槽位、预算显式调整保留计数、凭据形态阻止回信。App Server 模拟协议验证握手、嵌套工具禁用、继承模型、完成通知早于准入响应、拒绝交互授权、策略不匹配拒绝启动、冷恢复不调用新一轮模型及环境变量筛选。

原有派工、配置、安装及任务内问答测试继续执行，不跳过旧用例。本机最终全量 **177/177 通过**；发布检查为 0 错误、0 告警。Windows/Ubuntu CI 以对应提交的检查结果为准，不把本机测试等同于其他平台实机验收。

## 原生链路

环境：DSH 0.2.1-rc.3，WorkBuddy / DeepSeek‑V4.1‑Flash / high；Codex CLI 0.164.0-alpha.11.1，实际顾问模型 gpt-6.1-sol / high；原 placement companion v0.2 保持不变。独立消息包通过原生 `pluginManager/installBundle` 安装并加载，没有覆盖运行中的旧包。

1. 按已选 office 目标核对实例和工作区，配置独立项目成员及受保护连接。启动本机回环收件箱服务。
2. 用 DSH 原生创建接口建立测试会话，**没有 Hub job**。模型调用 `hub_ask_advisor` 一次后结束本轮，消息真实进入持久收件箱。
3. 调度器通过 stdio App Server 创建独立顾问线程，实际模型返回建议 `ADH_TEAM_OK=blue`。没有使用用户当前桌面主对话。
4. 建议排入原 DSH 会话。通过 owner API 核对该回信 requestId 只出现一次，原工作区与 cwd 未变；原会话随后执行写文件，磁盘产物为 `ADH_TEAM_OK=blue`。
5. 顾问进程退出后，使用另一个客户端按原线程/turnId 冷读取，恢复出同一回复，没有再次调用 `turn/start`。
6. 收紧 Shell、图片、插件、子代理和环境变量后，通过成员 HTTP 客户端提交另一个独立请求，沿用同一专属顾问线程，真实回复 `ADH_TEAM_HARDENED_OK=blue` 并送回原 DSH。沙箱/禁止交互批准由原生响应核对；此项验证顾问加固后的实际模型路径，不冒充另一次 DSH 原生工具发问测试。

另外通过新的 stdio MCP 客户端核对 20 个工具，实际调用成员列表、重复发信、回执与恢复入口：原消息 ID 保留，未泄露成员 token，模型准入计数没有增加。最终顾问原生轮次中没有工具执行项，冷恢复也没有重新启动模型。

本机联调最初遇到配置表覆盖及安装版准入参数兼容性拒绝；当时没有进入模型推理。明确拒绝与丢失确认分开处理，保留计数和回执，修正后由负责人显式恢复。没有用重新发送不确定请求绕过问题。

原始回执、原生日志摘要和磁盘证明放在运行机器的仓库外私有目录；不提交会话历史、真实路径、成员 token 或认证链接。

## 实际限制

首版是项目级独立求助与建议回传，不是多人群聊或任意桌面会话的唤醒器；不自动把新消息发到用户忙碌的主对话。服务须运行；顾问未启动可排队，Hub 自身不可达不声称送达。

真实跨平台、其他 CLI/DSH 版本、远程 HTTPS 代理和其他模型提供方未验收，均仅有模拟或接口边界测试。没有货币账单对照，不宣称节省积分。模型准入次数是累计预算，不是 token/费用硬上限。

旧 CLI 不提供任意只读根限制，本版不声称 read-only 等于强制读根隔离；顾问使用提供的上下文，并关闭已知命令/图片/外部工具能力。没有做面向恶意 OS 用户或未知插件的安全隔离证明，也不把凭据形态检测当成完整 DLP。未知线程创建准入和遗留事务锁继续保守阻塞，需管理员核实，不按年龄自动解锁。
